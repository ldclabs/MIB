# MIB 规范

## 记忆智能基准（Memory Intelligence Benchmark）—— 格式 v0.2，度量修订版本 0.5.0

[ [English](../MIB-Specification.md) | 简体中文 ]

**实现版本：** 0.14.1。**状态：** 规范性可执行开发规范。

本修订版本落实了 2026 年 9 月 23 日的第二轮设计审查。详细实施台账见[此处](harness/MIB-v0.5-Review-Resolution.md)；上一修订版本的台账见[此处](harness/MIB-v0.4-Review-Resolution.md)。早期修订版本的分数与本版本分数不可互换。场景格式保持为 `mib: "0.2"`；核心程序（Core Programs）与核心开发 Profile 为版本 0.5.0（Mechanism Challenges Profile 为 0.2.0），新的题库报告使用 `report_version: "0.6.0"`。静态 v0.1 场景依然保持可执行。

代码实现、Schemas 以及本规范共同定义了可执行契约。提案与归档文档仅作为设计推导背景，不作为与之竞争的规范。

# 0. 评测范围与解读

MIB 评估智能体（Agent）如何利用历史信息改善后续的作答与行动。直接使用原始历史记录是一种合法的记忆实现方式。单纯的长历史或反事实内容置换并不能独立证明持久化记忆机制的使用。

基准提供两种开发机制：

- **历史信息使用（Historical information use）：** 由声明的历史、任务分布及资源条件来定义评估结论。常规的 S/M/Expanded/Load Profile 均采用此机制。
- **跨会话持久性（Persistence across sessions）：** Session Profile 测试显式的 `session_boundary` 操作。固定模型包装器会持久化任务经历并清除瞬态对话上下文。集成的 Agent 自行实现并声明其自身的持久化边界；但这并不是其内部状态的独立证明。

得分取决于其程序集、Profile 版本、距离阶梯档位以及资源机制。它并不是对通用记忆智能的已验证度量。目前尚未完成真实模型的发布级校准，亦未冻结官方生成的排行榜题库。

# 1. 主旨与因果识别

## 1.1 主旨

过往经历在相关时应当影响未来决策，在无关时应当保持中立，在被撤回或过时后应当停止支配决策。

## 1.2 可观察的区分

MIB 区分答案值准确性、认识状态、信源归属、世界状态结果、首试行为、适度迁移、承诺履行行为以及操作性撤回。正确的外部行为并不等同于从所有内部存储中均完成了物理删除。

## 1.3 因果识别的局限

相关历史消融用于评估扣留该历史所产生的效应。内容孪生用于检验回答是否跟随变更的历史内容。策略孪生用于检验行为是否跟随在习得反馈中学得的潜在惯例。这些属于不同的干预手段。

保持曲线描述了在声明距离下的表现变化。它们本身并不能将存储、压缩、检索、推理或上下文窗口机制相互剥离。关于持久性的论断需要显式的会话边界机制及其实现假设。关于效率的论断需要具体的成本测量，而不能仅凭历史长度。

# 2. 基准体系结构

## 2.1 评测轨（Tracks）

**Track A —— 记忆系统（Memory System）：** 评测方锁定基座模型、提示词、解码参数、工具、任务环境以及推理策略；仅改变记忆系统。同模型测试框架实现了该实验。

**Track B —— 集成智能体（Integrated Agent）：** 允许整个 Agent 自由构建。托管的外部 Agent 服务接收此评测轨。它会拒绝将任意外部 Agent 作为受控 Track A 实验提交的企图。

在排名或配对对比中，**严禁（MUST NOT）**将不同的评测轨、Profile 标识/版本、题库包标识/版本、源码包以及度量机制混合在一起。

## 2.2 能力维度

修订版本 0.5 的 Profile 采用六个维度：留存与检索（retention/retrieval）、时序记忆（temporal memory）、认识记忆（epistemic memory）、规程记忆（procedural memory）、前瞻与自我记忆（prospective/self memory）以及撤回合规性（withdrawal compliance）。`procedural_memory` 同时涵盖反馈驱动的再现（同一项目族再次出现）与系列范围的适用性（已知系列的新项目族）；二者均属于由可见标识符索引并通过相同的合取式世界状态结果评分的配方回忆，因此本质上是同一个被重复度量的构念。遗留的 `experience_memory` 与 `skill_learning_transfer` 标识符对于修订版本 0.4 和 v0.1 工件依然有效；`selective_forgetting` 涵盖操作性撤回测试线，并不意味着全面的物理删除或具备预算意识的遗忘。合并改变了综合权重，因此修订版本 0.4 的综合分不可直接对比。

因果量属于诊断指标。它们不计入 v0.2 的能力维度。已废弃的 v0.1 `causal_memory_impact` 维度保留用于遗留 Profile。

## 2.3 Profile

Profile 用于锁定其标识/版本、评测轨、规模尺度、官方有效性标记、程序集与参数、阶梯配置、规范档位、实例种子或评测方抽样策略、重复次数、维度权重、覆盖率要求、统计方法、依赖性策略以及度量机制。

程序可以覆盖其阶梯配置并提供 `params`。阶梯优先级的顺序是：程序条目中的配置，然后是数据包/Profile 默认配置，最后是程序内置的默认配置。公开生成、隐藏具象化以及同模型校准共享此解析逻辑。交织回忆程序接受 8 到 4096 范围内的 `fact_count`。生成的私有存储清单必须与 Profile 的程序集、参数、有效程序级阶梯以及会话机制完全匹配。注册阶段会拒绝不匹配的配置；执行阶段会检查每个实例的程序/版本、阶梯档位以及干扰计数，并要求每个种子都具备该程序的所有档位。

随附的开发 Profile：

| Profile 后缀 | 程序数 | 阶梯 | 用途 |
|---|---:|---|---|
| `Dev` | 7 | 0 / 20 / 100 | 核心集成与受控实验 |
| `Dev-M` | 7 | 0 / 100 / 1000 | 更长干扰距离；BCa 置信区间 |
| `Expanded-Dev` | 14 | 0 / 20 / 100 | 每个维度两个语义机制 |
| `Session-Dev` | 14 | 0 / 20 / 100 | 显式会话边界 |
| `Load-Dev` | 14 | 0 / 20 / 100 | 交织回忆中包含 64 个有益事实 |
| `Calibration-Dev` | 14 | 0 / 20 / 100 | 评测方拥有的固定模型实验 |
| `Horizon-Dev` | 7 | 100 / 2,000 / 10,000 | 集成 Agent 的长可见历史；仅运行头条指标 |

以上均为 `official: false` 的开发 Profile。更多数量的种子或更复杂的置信区间计算并不能确立更广泛的构念有效性（construct validity）。

修订版本 0.5 的 Profile 声明 `measurement_regime.intervention_rungs: "canonical"`：干预措施仅在规范档位（canonical rung）运行，因为其他档位的干预均不进入任何聚合，而其他档位仅为保持曲线运行完整条件。它们还声明 `maintenance_control: "declared_maintenance_only"`：仅对声明了维护能力的 Agent 运行无维护重放，否则该运行只是重复完整条件且导致 `consolidation_benefit` 无法评估。没有这些字段的 Profile 保留所有干预措施。`measurement_regime.diagnostics: "off"` 还会跳过相关消融、无关消融、危害对照、无维护对照与负迁移对照：头条指标（各维度得分与依赖门槛）仅需要完整条件与孪生对照，而各项对照仅用于输入因果诊断量。Core Dev 在开启诊断时运行 377 个条件，关闭诊断时运行 182 个条件，头条结果逐位相同。`measurement_regime.session_isolation: "persisted_state"` 使得会话边界被强制隔离执行（§5.2）。

## 2.4 数据包（Packs）

生成的题库包严格由 `Programs × seeds × rungs` 构成，不存在缺失或重复的实例。公开的生成构造并不构成在参赛者接口暴露语义事件角色的理由。当由评测方配置时，官方种子必须保密，并在交付前替换为带密钥的别名。

# 3. 角色与边界

Program（程序）负责构建世界、时间线、探针与干预措施。Runner（执行器）投递观测数据，控制世界状态演迁与工具执行，并记录行为。Evaluator（评测器）计算结果。聚合模块定义共享的评分泛函。评测服务对任务与结果工件进行签名认证。

参赛者可见的观测、交互、任务、请求、项目以及静态工具调用标识符均为不透明标识。它们的分布特征不得泄漏相关事实、干扰项、留存目标、前瞻探针或计分的未来任务的角色标签；没有任何参赛者可见的文本将项目标记为练习（practice）、保留（held-out）或评测（evaluation）材料。成对配对条件之间为对应项保留稳定不透明的别名。参与者身份以及常规的工具/数据语义保持可见，因为完成任务需要这些信息。

查询、Oracle 真值数据、评测器标签、支持集合以及干预标签均保持私密。可选的特权 Oracle 支持校准参考属于显式特权诊断项，绝不得作为参赛者得分或发布门控。

# 4. 场景模型

## 4.1 契约

`schemas/mib-scenario.schema.json` 定义了机器可读格式。语义校验器会额外检查执行支持、引用完整性、干预一致性以及生命周期锚点。在 schema 上有效但在语义上不可执行的构造将被拒绝。

## 4.2 程序与世界模型

`generate/` 构建确定性实例。独立的随机数流分别控制语义选择、表层词汇呈现、时钟、干扰、干扰措辞、respond 探针顺序、不透明标识符、提问对照以及内容孪生。探针表述与可接受答案在同一组种子的各个阶梯档位之间保持恒定。

评测方可以提供私有表层措辞库（surface bank，包含陈述/提及/撤回模板、提问提示词以及程序固定短语）。它仅改变措辞表达：语义抽样、世界模型断言以及所有 Oracle 均保持不变，且实例会记录 `surface_bank_digest`。针对公开语法的解析器预计无法迁移到该私有库上。隐藏种子保护的是实例答案；唯有私有表层措辞才能防范针对公开语法的特化解析器作弊。承诺、准则和任务简要的措辞目前尚未纳入该词表覆盖。

世界模型记录带有信源、主体、属性、取值、类型、观测序列、可选有效区间、更替关系以及可选推导依赖的断言。它将具备真值效力的断言与单纯的陈述和非断言性提及清晰区分开来。

- 状态/更新（State/update）断言描述状态变化。
- 修正（Corrections）会溯及既往地替换被修正血统分支的值，包括链式修正。原始陈述在被撤回前依然可被陈述历史查询所检索。
- 疑问句与假设性陈述在这些受控世界中不确立任何事实。
- 撤回（Retractions）会从操作真值、证据与历史的所有层级中移除指定的断言血统及依赖推导。撤回后该属性重归未知。全新且独立的授权与断言可以确立新值。
- 双时态（`bitemporal`）查询区分有效时间（valid time）与记录可用性截止时间（record-availability cutoff）。未来公布的事实不会自动成为当前生效事实。
- 作用域权威（Scoped authority）可表示为普通的可见权威记录。`according_to_authority` 解析指定的信源；仅靠全局信源权重不能判定断言真伪。

查询包括 `current`、`as_of`、`first_stated`、`said_by`、`known`、`status`、`hop`、`bitemporal` 以及 `according_to_authority`。优先的当前值仍可能处于争议（contested）状态。向特定信源归属与断言客观确定性是截然不同的两件事。

查询 Oracle 由模型结果推导得出。工作流预期由抽样的配方推导得出；前瞻预期由抽样的责任义务推导得出。这些推导均需经过独立测试与语义审查：使用生成器并不等同于证明其解释是正确的。

基础程序测试直接/多跳回忆、时序更新、修正/冲突、反馈驱动的工作流、适用性边界、前瞻/自我准则以及撤回。扩展程序测试交织负载、延迟修正、具有相同声明文本的作用域权威、修订后的规程、配方复合、已取消的承诺以及授权后的重新学习。

## 4.3 依赖需求与执行策略

所需的能力包括 `observe`、`respond`、`act`、`tools`、`virtual_time`，以及对于 Session Profile 的 `session_boundary`。要求会话边界的场景需要显式的能力声明。维护（maintenance）保持为可选能力。

执行限制约束 Agent 交互轮次与工具调用次数。认知/协议失败保持其探针权重，记为零分；传输/Runner 故障单独分类。不支持的特性绝不能静默转化为成功的覆盖率。

## 4.4 工具与世界

Runner 拥有并管控世界状态。静态的 deployment/workspace/contextual-save 模拟器依然可执行。

生成的规程任务使用 `mib.workflow.v1`。`workflow.submit` 为不透明的项目族执行有序配方。系统会记录首次配方、首次尝试正确性以及最终完成情况。失败的尝试会返回纠错反馈以供恢复。在首次尝试之前，未来的请求与工具描述均不会透露所需的配方。

训练与再现使用同族的相关项目。不匹配族拥有自身习得的配方；将第一族的配方应用到不匹配族属于错误。规程适用性检验在某项目族上学得的配方能否迁移到同一系列的新项目族，并在不同系列的新项目族上保持克制。修订工作流与复合程序测试不同的机制。在执行每个未来任务前都会重置任务状态，以防止训练过程意外完成该任务。

## 4.5 时间线与距离

事件包括交互、文档、工具结果、观测、亲历任务、世界更新、维护窗口、会话边界以及检查点。Runner 仅向 Agent 投递参赛者可见的信息。

噪声抽样采用完整的公开候选值池，独立于目标答案排除项。答案值可能出现在其他主体或疑问句中。正确解释必须取决于其关系与血统来源。这杜绝了通过候选池补集推导答案的作弊捷径。

同一种子的阶梯档位在改变干扰计数的同时，保持其任务与虚拟时间跨度不变。普通的干扰块即使在 rung 0 档位也跨越 24 个虚拟小时。交织回忆程序在时间流中穿插分布有益观测（包括维护之后），并将噪声分散在固定跨度中。其相似主体的噪声会排除所有主参与者，因此另一段噪声块绝不会覆写较早或未来的受测事实。

`interference_tokens` 是一个**遗留字段名，代表按空格分隔的词数（whitespace-separated words）**，而非分词器 tokens。报告严禁据此推断模型上下文溢出。Runner 输入/输出字节统计覆盖序列化的参数与结果；模型提供的 token 消耗（若可用）单独报告。不同的语义/负载 Profile 属于不同的实验。

## 4.6 探针与承诺

探针通过 `respond`、`act` 或 `observe_only` 投递。observe-only 探针使用常规的观测接口与不透明标识符。

前瞻生命周期评测器审查从声明的创建点到运行结束期间的所有发射行为。其 `expected[]` 项明确承诺标识、接收者、主题以及触发事件/探针。它统计遗漏（misses）、误报（false alarms）以及重复/多余的发射。生成的触发窗口为零次观测：提醒必须在触发观测到达的时刻立即发出。

提醒既可以是完全规范化的固定句式 `Reminder: ask <person> about the <topic>.`，也可以是命名了 `recipient` 与 `topic` 且 `type: "reminder"` 的载荷。载荷可以通过 `commitment_ref` 引用其承诺，该引用为 Agent 看到的该承诺的不透明观测 ID；若引用其他观测事件，或提供与评测方不同的显式 `commitment_id`，均判定为错误提醒。评测方的承诺 ID 绝不会展示给 Agent，也绝不作为要求。载荷可以省略 `content`；Runner 会保留这种缺失状态。如果有伴随文本，必须是规范固定句式。非对象载荷无法满足结构化匹配，但不会使正确的文本备选项失效，亦不会导致评分异常中断。仅仅在一堆候选主题中侥幸包含一个正确主题无法得分。承诺取消程序在取消一个承诺的同时，针对同一触发事件保留第二个依然有效的承诺，因此什么都不发射并不正确；其孪生对照则保持第一个承诺依然有效。

常驻自我准则指明允许/禁止的操作，并规定唯有显式的授权修订才能予以更改。常规的维护请求不属于撤销。合规性判定是合取式的（`eval-action-strict`，带有 `require_all` 的复合项）：允许的操作必须执行，禁止的操作严禁执行，且最终的世界状态必须匹配。什么都不做无法获得任何部分分。

后期抽样（Late sampling）仅在投递时选择输入变体；成对配对条件之间使用完全相同的变体，并保留其摘要以供验证。

## 4.7 评测判定

结构化标量值在规范化后采用确定性精确相等比较，并具备显式的 oracle 别名。容器以及在生成标量任务中的非字符串值均被拒绝；错误的值无法获得仅状态分（status-only credit）。否定公认值或罗列备选候选词不视为有效作答。显式的遗留文本 `contains` 评测器依然可用。

生成的标量评测器使用 `disclosure_scope: "withdrawn"`。已撤回的值（Oracle 中的 `withdrawn`）出现在可见输出的任何位置均判定为失败，包括在弃权声明、解释或信源归属中出现。其他禁用值（已更替、相冲突、仅提及）仅当它们作为答案本体时才判定失败；准确回忆历史的解释不属于采纳过时陈述，否则对解释的惩罚将随干扰阶梯不合理增长。未包含该字段的遗留评测器对所有禁用值保留全输出扫描检查。泄漏检查检查实际的叶子节点值，排除 JSON 字段名、null 占位符以及公认答案信封中根层级合法的 status/confidence 元数据。JSON 与按行键值答案采用相同的取值语义。无效元数据与嵌套辅助值仍需接受泄漏检查。

探针可以声明 `conditional_on`（依赖前置条件）：仅当在同一次运行中成功回忆出所命名的每个探针的值时，该探针方可得分。撤回探针依赖保留的邻居事实，认知弃权探针依赖修正后的正确值，状态探针依赖主张本身。因此，毫无记忆的系统无法凭默认猜测通过撤回、弃权或状态判定。探针保留其固定权重；前置条件失败得分记为 0 并标记为 `prerequisite_failed`，无条件得分则保留用于诊断。

结构化评测采用固定评分准则（rubric），通常为 value 占 0.8、status 占 0.2。缺失的必填字段在其固定权重上得零分；它们不会从分母中消失。带有明确答案值却声明 unknown 状态属于自相矛盾，判定为失败。合法的弃权可以表示为 null/unknown 或弃权信封包。

置信度代表表明答案值或弃权决策正确的声明概率。在系统提供了置信度时，会报告 `1 - (confidence - value_correctness)^2`。当评分准则赋予置信度正向权重时，遗漏置信度将在该权重上得零分。在其他情况下，它不构成能力加分项。

世界状态评测器检查显式条件；`eval-world-strict`（`require_all`）使其成为合取式判定。轨迹评测器检查必选/禁用动作、调用顺序、发生次数以及无复发要求。计分的工作流探针是合取式的：首次配方正确与最终完成必须同时成立。先前对其取平均值使得在任务内根据模拟器反馈进行重试的无记忆策略获得了 50% 的分数；`RecoverOnlyAgent` 是必须保持为 0 分的公开测试 fixture。

发射评测基于整个声明生命周期内可观察到的实际发射行为，而非 Agent 声称自己记住了的言论。

## 4.8 干预与证据

- 相关/无记忆消融（Relevant/no-memory ablation）在保持常规世界重置不变的前提下扣留指定的观测或亲历任务。
- 无关消融（Irrelevant ablation）检验稳定性。
- 内容置换（Content swaps）替换断言或承诺，并重新推导受影响的答案/义务。每个枢轴事件（pivot event）存在一个孪生对照，并对答案发生改变的每个探针进行评分。其取值仅从普通（非干扰）事件中选取，从而在各个阶梯档位保持恒定：优先选择普通事件中从未为该属性提及的值，次选主体自身血统之外的值。孪生绝不能是对主体已有旧值的无变化“更新”（no-op change）。历史探针同样具备孪生对照。
- 策略孪生（`counterfactual_policy`, `replay_policy_twin`）在习得与未来验证中一致地改变潜在的工作流配方。它们只能改变配方本身，不能改变族标识或操作初始化。它们属于匹配的规则世界诊断项，而非仅涉及历史的 Memory Benefit 对照。
- 无维护重放（No-maintenance replay）扣留维护窗口。
- 负迁移对照（Negative-transfer control）扣留某一个族的习得过程，同时保留对不匹配任务的支撑。
- 生成的提问条件使用位于相同位置、同一发言人、字数相同的无关提问作为 `reference_ablation` 安慰剂，并从其自身的数据流中抽样被提问的备选值。其危害对照使用的是该安慰剂，而非较短的完整时间线。

符号级支撑检查仅能确立在查询引擎下的不可推导性。它不能确立词汇、元数据或分布层面的无泄漏。针对这些信道需要独立的对抗测试。

## 4.9 权重

探针得分为加权平均值。场景维度证据权重之和为 1。Profile 维度权重定义能力综合得分。诊断/对照执行不增加能力权重。

## 4.10 验证

验证环节检查 schema、唯一 ID、所有引用、受支持的工具/方法/操作符、生命周期锚点以及世界策略约束。提问注入不能直接变更世界状态。只有显式声明类型的策略孪生才能替换受支持的潜在工作流策略。

# 5. 执行

## 5.1 题库包执行

每个实例与重复轮次均执行完整条件及其声明的干预措施。每项常规干预措施均执行完整的未来探针序列；仅其声明的评分受测子集对相应的对照做出贡献。这可防止较早探针的行为差异成为时间安排中未记录的隐藏变量。

## 5.2 隔离性

各条件使用全新的 Agent 实例/重置上下文，配备成对配对的种子与未来输入。托管的 stdio 条件使用独立的沙箱进程。当 `session_isolation` 为 `persisted_state` 时，Runner 会在会话边界重建 Agent 实例，并仅回灌其返回的状态字符串（§5.3）。在其他情况下，远程/HTTP 状态隔离仍属于声明式契约与开发传输限制。

## 5.3 亲历经验与生命周期

Agent 执行训练任务并获得真实的工具反馈。任务结果属于学习诊断项，不计入能力基准分。

同模型适配器记录当前目标、尝试的操作、反馈以及完成情况。B1–B3 在任务完成或进入下一个任务前持久化任务轨迹；B0 则予以丢弃。会话边界在清除瞬态对话的同时保留所选的持久记忆条件。在实验启用时，观测期决策与维护属于显式的模型操作。

## 5.4 故障分类

认知故障（包括协议误用或耗尽动作预算）属于计分的失败。执行故障仍计入分母，并贡献于执行故障率。Profile 的执行故障率上限同样构成官方有效资格门控；托管排行榜默认采用零容忍策略。

## 5.5 证据工件

运行工件（Run artifacts）包含探针结果、任务试验、因果有效性、未来输入摘要以及聚合所需的充分统计量。私有轨迹包含发射的消息、动作/经历轨迹、世界结果以及操作遥测。公开的隐藏报告会隐去原始运行记录与私有标识符。

# 6. 能力评分

## 6.1 探针与场景

在计分与执行失败的尝试上：`S = sum(probe_weight × probe_score) / sum(probe_weight)`。执行失败贡献 0 分，并保留其权重。

## 6.2 实例

对完整条件的重复轮次取平均值。维度归属遵循探针标签。实例还会保留其阶梯档位、干扰词数/计数、虚拟距离以及反事实证据计数。

## 6.3 模板 / 程序

在每个程序内，仅对处于 Profile 规范档位（canonical rung）的实例取平均值。其他档位仅对保持曲线做出贡献。

## 6.4 维度

`D[d] = 100 × weighted_mean(Program dimension scores, Program evidence weights)`。

## 6.5 MIB 综合得分

`MIB = weighted_mean(D[d], Profile weights)`。未实现全局防护栏惩罚。覆盖率统计所有要求的程序，包括不支持的程序。覆盖率不足判定为局部结果（partial）。

`official` 字段代表在声明策略下的准入资格：官方 Profile、要求覆盖率、依赖性策略以及执行故障率上限必须全部通过。唯有受信评测方接受的评测周期与密码学证明才能确立官方发布权威；本地未签名的 JSON 标记不具备此效力。

## 6.6 共享评分泛函

`aggregation.py` 被题库包执行、配对系统对比以及策略验证共同使用。缺失证据严禁静默改变维度权重。遗留的静态评分使用其声明的模板层级结构。

# 7. 诊断指标体系

## 7.1 配对机制

配对对共享实例、重复轮次、Agent 种子以及未来输入摘要。备选的危害参考必须是在相同探针子集上声明的匹配无关记忆对照。无效配对不贡献任何因果证据。

## 7.2 记忆收益与内容追踪

`MB = F - R`（带符号）。`HMB = max(0, F-R)/(1-R)` 排除消融得分处于上限 0.02 范围内的情形。

内容追踪以完整条件探针回答正确为前提，并要求在变更后的 Oracle 下完全正确。合格探针数为零属于未定义，绝不能作为零追踪率的证据。原始合格/总计数与成功计数分别保留。在修订版本 0.5 的 Profile 中，由内容跟随效应（§7.10）取代其作为依赖门槛；内容追踪仍保留为诊断指标。

内容孪生与策略孪生覆盖所有七个基础维度，包括变更的承诺、自我准则以及撤回指令。干预类型在评测方证据中保持可见。

## 7.3 无关记忆稳定性

`IMS = clamp(1 - max(0, abs(F-I)-tolerance)/(1-tolerance), 0, 1)`。

## 7.4 记忆危害

`MH = max(0, C-H)`。生成的提问线使用其匹配的安慰剂作为 C。`HRS = clamp(1 - max(0, C-H-tolerance)/(1-tolerance), 0, 1)`。这些是声明构造下的对比；它们并不能确立所有现实世界中的记忆投毒形式。

## 7.5 净记忆增益

`NMG = MB - MH`，仅作诊断用。

## 7.6 遗留因果维度

对于 v0.1 Profile，保留原有的以收益门控的因果复合分。v0.2 Profile 不将其作为能力维度赋权。

## 7.7 证据与不确定性

严禁以程序数量代替合格探针配对数。聚合逻辑保留计数，且依赖性统计块额外记录独立的实例单元。描述性比率与因果对照具有不同的统计学解读。

## 7.8 负迁移

对比在有和无另一族习得经历下的相同不匹配任务表现：`NT = max(0, without_skill - with_skill)`。报告伴随的行为失败率与抵御度。不匹配探针位于匹配探针之前，以防止对照组提前重新学得被扣留的规程。

## 7.9 行为诊断量

错误复发（Recurrence）要求 Agent 确实在先前亲身经历过相应的失败。工作流复发要求匹配族与所需配方；未见过的修订规则不属于先前经历过的错误。首次尝试失败与最终完成属于独立条件。学习增益是最后一次试验得分减去第一次试验得分，报告的曲线下面积（AULC）为平均试验得分。

新增的 `memory_related_error_rate`（记忆相关错误率）属于描述性错误模式比率。它不声称因果归属。`memory_induced_error_rate` 为旧报告接受的遗留名称。信源归属、历史保真度、权威混淆以及自我准则延续度均保持为描述性诊断量。

## 7.10 记忆依赖性准入门槛

依赖门槛要求在每个有权重的维度上均具备证据。它采用内容跟随效应（Content-Following Effect, CFE）：在每个冻结的测试机会上，探针输出在孪生历史下是否携带孪生值，减去其在原始历史下是否携带该值（对于结构化答案取值部分）。分母为所有计划中的 full/twin 探针配对；无法评估的配对计为未跟随。总是输出相同答案、或毫无记忆的策略，其期望效应为 0。

重复轮次在实例内部取平均。门槛在每个固定的程序层内计算实例均值，随后在维度内对各层取平均。每个有权重的维度需要 5 个完整的独立实例、100% 的有效计划配对覆盖率，以及至少 0.2 的实例聚类百分位 bootstrap 置信下限（默认为 95% 置信度，2,000 次抽样）。重采样保持程序层固定。重复轮次不得增加独立样本计数。缺失的对照判定为无法评估。该门槛的选择是为了在声明样本量下具备统计功效：在每个实例仅 1 个机会的情况下，能够跟随 90% 变化的系统在模拟的 5 种子题库包中以至少 80% 的概率通过所有七个维度，而候选池随机猜测通过率至多 5%（经过回归测试；在 200 个题库包模拟中实测分别约为 97% 与 0%）。跟随 70% 变化的系统通过率约为三分之一：5 个种子依然无法证实微弱的依赖性。

`joint_twin_success`（完整条件与孪生条件均完全正确）作为诊断量分维度报告。它近似于准确率的平方，因此作为门槛时实质上是能力准入门槛：在 5 个种子下，具备 90% 联合成功率的系统在修订版 0.4 门槛下的通过率仅约 15%。条件内容追踪仍单独报告。修订版 0.4 的 Profile 保留 `joint_twin_success`，遗留 Profile 保留其显式声明的条件/Wilson 策略。

这些是待校准的开发策略选择，而非已确立的心理测量学阈值。CFE 仅确立回答在声明构造下跟随了声明的历史；它并不能识别特定的持久化记忆机制。简并的经验 bootstrap 区间会显式标记，且不能确立总体确定性；5 个完全成功的实例不能证明广泛的通用性。正式的样本量与有效效应量阈值仍需要预先登记的 pilot。

# 8. 统计分析

## 8.1 保持曲线

每个阶梯档位按程序分别报告。`retention_index`（保持指数）为各档位得分的算术平均值，而非物理距离曲线下的尺度不变面积。半衰距离（Half-distance）在阶梯曲线跨越 rung 0 表现的一半时通过线性插值求得。若得分从未低于一半，则报告为超越阶梯范围。

## 8.2 Bootstrap 置信区间

生成数据包保持程序集合固定，对规范档位实例进行重采样，并在每个实例内部对配对重复轮次进行重采样。静态数据包按文档对模板进行重采样。置信区间采用百分位法或 BCa 方法，在简并情况下具备显式回退。

置信区间以声明的程序集以及充分的样本量为前提。它们并不衡量关于语义设计选择的不确定性。增加重采样次数并不能弥补真实观测数据极其匮乏的问题。

## 8.3 规范档位

能力得分、依赖性门控以及得分置信区间均使用相同的规范档位（canonical rung）。完整的保持曲线保持独立。

0 / 20 / 100 开发 Profile 的规范档位展现约 970–1,500 个可见历史字符（Core），在最高档位至多约 5,400 个字符。若集成 Agent 的上下文窗口能够容纳如此规模的历史，则其实际处于裸上下文机制（raw-context regime）下：得分无法将长上下文阅读与记忆机制剥离开来，且能力卡片会将可见历史字符范围与得分一并展示。`Horizon-Dev` Profile 在 2,000 个干扰事件档位（约 90,000 个可见字符）读取能力得分，并配备 10,000 个事件的保持档位（约 450,000 个字符）。长可见历史是 Runner 唯一能够施加于集成 Agent 之上的记忆压力。

## 8.4 配对对比

对比要求匹配的 Profile/版本、评测轨、规模尺度、题库包、评分修订版、策略、权重、规范档位以及完整的配对实例覆盖。生成式对比不会抽样排除程序或混入其他阶梯档位。点估计差异与置信区间均使用相同的共享评分泛函。

# 9. 报告与核验

## 9.1 标识

评测结果必须指明其 Profile/版本、评测轨、题库包/版本、规范档位、度量机制、Agent 标识以及可执行源码摘要。同模型实验还会锁定模型配置、提示词、解码参数、运行时记忆策略以及源码哈希。

## 9.2 核验级别

新报告嵌入了与评分相关的评测策略以及要求的程序证据权重。完整核验会重新计算运行/实例聚合、因果证据、依赖性决策、覆盖率、官方有效性、保持曲线以及可用的置信区间。公开脱敏核验会检查策略与保留的聚合数据；它无法重构私有执行过程。

Bootstrap 估算与重放使用运行工件（Run Artifacts）携带的有效消融容差。缺少私有消融定义的精简模板描述符并不意味着容差为零。没有携带容差的遗留工件在估算时可以使用场景声明。

展示的置信区间必须与统计配置块一致。篡改依赖性门控、官方标记、聚合因果值、保持曲线或置信区间的报告将被拒绝。新报告要求匹配的可执行源码包以复现其解读。

算术一致性、源码标识一致性、服务认证证明、受信 Profile 准入以及科学有效性属于截然不同的论断。

## 9.3 成本度量

Runner 遥测记录针对 observe、respond、act、maintenance 以及 reset 的调用次数、输入/输出 UTF-8 字节数以及挂钟毫秒耗时。工具调用与探针延迟依然保留。同模型遥测还会额外记录服务商提供的 token 消耗与记忆截断。

本套件并不独立测量每个外部系统的存储量、写放大或后端算力。有界内置上下文与外部上下文共享硬性最终渲染字符上限（包括前缀与分隔符）。同模型实验报告 `memory_pressure`（记忆压力）：渲染的可见观测字符除以每个有界臂的预算（这是一个下界，因为亲历任务轨迹与对话还会增加更多字符）。超出限制的记录将被整条略去并予以报告；null 上限明确代表无界参考。字符不是分词器 tokens。核心带符号与截断的分数差异使用 JSON 单位 `normalized_delta`；前端展示乘以 100 显示为百分点。请使用预算受控的实验并报告质量/成本对；严禁将按空格分隔的词数或探针延迟单独解释为记忆效率。

# 10. 基线校准

生成的校准框架具象化每个程序/阶梯/种子，并在固定的模型/提示词/工具/解码配置下轮替平衡 B0 无记忆、B1 全可见历史、B2 词法检索以及 B3 启发式显著性选择。它包含内容与策略孪生对照以及匹配的危害/安慰剂对照。

可选的附加测试组用于测量无界完整历史参考基准、有界近期上下文与特权 Oracle 支持的参考基准。每当 B1 有界时，无界参考基准即充当发布门控的 full-context 臂；其余两组仅作诊断用，不计入核心得分，且不保证构成数学上的理论上限。

在预算约束下对各记忆臂进行比较，唯有当预算在每一个臂中均实质生效（bind）时才具有信息量。当 B1–B3 中有任何臂受预算约束且实验目的不为 `smoke` 时，预检要求每个有界臂的中位数历史/预算比率达到 `calibration.min_memory_pressure`（默认 1），并要求每个臂的选择策略能够填满其预算：B2 保留 `retrieval_top_k` 条记录，B3 至多保留 `structured_top_k + structured_salient_k` 条记录，因此 `top_k` 乘以渲染记录的中位数大小必须达到预算上限（`selection_capacity_chars`，`budget_binds`）。否则，各臂之间的差异反映的是容量差异而非策略差异，该次运行将被直接拒绝。有界的 B1 被标记为 `most_recent_visible_history_within_budget`，属于近期窗口而非完整上下文：此时 `full_context` 门控、记忆区分度指数以及记忆差距分母均改用 `unbounded_reference` 附加基线（无预算约束的 B1），该基线必须无截断运行；若缺少该基线，上述门控均为无法评估。包含无界臂的实验属于 `unbounded_reference` 机制：此时 B1 属于完整历史参考，而 B2/B3 仅因选择策略而不同，这不属于有预算约束的架构比较。

`same-model-generated.stub.json` 是一个工程冒烟配置。`same-model-generated.external-http.json` 是开箱即用的真实模型实验配置（采用无界参考）。`same-model-generated.pilot.json` 在 100 个干扰事件档位运行，每个记忆臂分配 3,500 字符的预算（中位数历史/预算比率约为 4.2，要求至少为 4），其选择容量足以填满该预算（B2 采用 top-30，B3 采用 24+8 条记录，单条渲染记录约 140 字符），并包含无界参考臂。模型服务端点、不可变模型标识与凭证属于外部输入。测试桩的执行不能确立任务难度、区分度或发布就绪状态。无状态性预检可以检测到某些违规情况；但它不能证明远程服务绝对没有保留状态。

应根据先导试验方差和预先登记的最小有效效应量来选取真实的样本量、重复轮次与准入阈值。在做出跨架构通用论断之前，应当测试多个固定模型。官方题库包的冻结仍取决于这些实证结果。缺失或不完整的必要因果指标判定为无法评估（`unassessable`），而非通过。无效的完整/因果生命周期将阻断准入。冒烟与先导配置绝不授予发布准入资格。校准种子、重复、阈值与用途设置均绑定在实验锁中。

当受预算约束的 B1 使用无界参考臂（unbounded reference）进行准入判定时，该参考臂的调用与运行也将进入模型/提示词/解码一致性检查、传输/解析错误计数、生命周期检查以及配对种子/未来探针审计。公平性调用总数包含该参考臂；其遥测数据保留在 `additional_baselines.unbounded_reference` 中。条件执行顺序审计依然保持 B0–B3 的轮替平衡。未用于准入判定的额外参考臂依然仅作诊断用途。

# 11. 治理与隐藏评测

生成的私有存储使用保密的带密钥种子与公开的程序构造。存储与 Profile 配置必须一致。评测任务绑定私有存储、Profile、schemas 以及可执行源码包。评测结果绑定报告摘要并由服务进行数字签名。

服务会拒绝评测轨不匹配的提交，并在排名中排除局部、非官方、策略未达标或无效的报告。托管的外部提交属于 Track B；Track A 使用评测方受控的同模型测试框架。

公开报告会脱敏原始运行记录、种子、私有模板 ID、迁移支撑细节以及仅评测方可见的内容。仅限 Linux 的进程隔离仍属于平台限制。HTTP reset 与远程模型无状态性仍属于声明式契约。当前实现并不声称具备硬件级证明或已完成生产环境部署。

# 12. 不变量与后续实证工作

1. 架构中立并不意味着实验资源可以不加明确说明。
2. 常规的参赛者可见元数据不得透露探针或相关性角色。
3. 扣留历史时保持常规的未来世界状态重置不变。
4. 策略孪生是对潜在惯例的显式类型变更，而非伪装的纯记忆消融。
5. 首次尝试正确性与真实经历的失败是可观察的。
6. 缺失的计分字段不会缩小评分准则权重分母。
7. 撤回的评估基于可见输出，而非自报状态。
8. 前瞻记忆检查覆盖整个声明生命周期内的误报。
9. 能力分、依赖性与对比分析采用一致的聚合逻辑与规范档位。
10. 缺失的因果证据保持为缺失；计数保留其统计学基元单位。
11. 生成的 Oracle 需要经过独立验证。
12. Fixture 排序属于管道验证证据，而非真实模型校准。
13. 毫无记忆的策略无法获得结构性底分：`GrammarOnlyAgent`（遵循公开语法默认值，无历史）在每个 Core 与 Expanded 维度得分至多为 10，且无法通过依赖门槛（经过回归测试；实测当前为 0）。
14. 有预算的记忆比较要求预算实质生效；依赖门槛度量的是内容跟随性，而非准确率。

实现这些构造并不意味着完成了进一步的实证验证、真实系统存储/成本插桩、更广泛的独立领域验证或官方题库冻结。迁移智能（Transfer Intelligence）保持为补充诊断；除非有充分的更强路由假设，否则其早期/晚期产物对比度量的是涵盖形成、留存与检索的综合可用性。MIB-R 保持为独立的原型结果族，其在外部任务上的效用需要自身的专门校准。

# 13. 开发挑战与入口

`MIB-Mechanism-Challenges-0.1-Dev` 增加了针对未见项目族的基于特征的配方复合，以及多重承诺/取消/续期/重复触发行为。它是一个独立的 Profile，并非 Core 分数的扩展。特征任务提供复合惯例，但具体操作必须来自真实反馈；它测试的是有界复合，而非开放式的规则发现。

通过 `mib run` 运行场景、生成的 Profile、同模型配置、内存后端配置或纵向实验配置。`mib compare` 对比兼容且已核验的题库报告；`mib verify` 是 `verify-score` 的别名。现有命令依然受支持。场景/Profile 运行需要 `--schema`；已配置的实验自行解析其 schema 与提示词。`same-model-generated.pilot.json` 是一个有界、包含七种机制、单阶梯档位且施加记忆压力的 pilot；现有的 stub/full 配置保持独立。

可选的 `observe_decision_types` 根据公开观测类型路由业务模型的观测决策。所有观测仍会进入记忆形成。相同的声明路由器应用于每个记忆臂，且绝不读取探针、相关性、Oracle 或触发标签。
