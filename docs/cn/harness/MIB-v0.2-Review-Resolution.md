# 2026 年 9 月设计审查决议

度量修订版本 0.3.0；实现版本 0.10.0。最初的审查针对 `50bba8b`，随后对修正前 commit `673631a` 进行了跟进审查。此前按要求未同步中文镜像。未调用任何子智能体（subagents）。

## 决议台账

| 审查关切项 | 决议方案 | 验证 / 范围 |
|---|---|---|
| 弃权声明中隐藏已撤回内容 | 独立于状态检查所有可见输出字段；不一致的 unknown/value 组合判定为失败 | 回归测试用例覆盖结构化值、解释、纯文本以及弃权信封包（abstention envelopes） |
| 可选字段缩小评分准则权重分母 | 固定 value/status/confidence 分母 | 缺失必填字段无法获得额外加分 |
| 语义标识符泄漏 | 成对配对条件之间使用不透明的对应 ID | 捕获测试与重命名不变量测试 |
| 前瞻误报与主题盲目喷洒 | 覆盖完整声明生命周期，严格匹配接收者与主题，拒绝重复或无关的发射 | 提前发射/喷洒回归测试；活跃/已取消承诺孪生对照 |
| 候选值池补集答案泄漏 | 噪声生成忽略答案排除项，从完整候选池中统一抽样 | 不同排除答案集合下的同噪声测试 |
| 通用规程作答策略作弊 | 实例特定配方、真实训练反馈、首试判定准则、不匹配/修订/复合任务 | 无状态脚本模型测试严格区分 B0 恢复与 B1 复用 |
| 依赖性门控过于宽泛及计数单位不准确 | 分维度证据、探针与实例计数、最低覆盖率/实例数门槛、Wilson 置信下限 | 缺失证据与篡改测试 |
| 配对置信区间错误引入其他干扰档位 | 共享聚合逻辑；生成包仅针对规范档位配对实例执行 bootstrap；严格的兼容性要求 | +100 人工配对用例当前产出 [+100, +100] 区间 |
| 同模型生命周期与外部钩子缺失 | 为 B1–B3 持久化亲历任务轨迹；清除 B0/瞬态状态；支持观测期决策/维护；HTTP/stdio 转发完整生命周期 | 脚本化无状态模型与 HTTP 往返测试 |

| 距离阶梯改变了底层任务 | 独立随机流；完整的请求不变量；固定的虚拟时间跨度 | 所有已注册程序在各阶梯档位下均通过校验 |
| Oracle 链式关系与语义覆盖不足 | 链式修正、双时态查询、权威记录、级联依赖撤回、重新授权 | 独立的真值表与血缘测试；七个新增的语义程序 |
| 排名与报告解读核验不足 | 策略与源码绑定、共享重新计算、门控/官方/保持/区间核验；评测服务轨道与准入限制 | 防篡改回归测试与生成公开报告核验 |
| 因果命名歧义 | `memory_related_error_rate`（记忆相关错误率）界定为描述性指标；迁移智能的早期/晚期对照界定为产物可用性（artifact availability） | 规范文档、报告 schema 以及能力卡片完成同步更新 |
| 信息负载与资源假设 | Expanded/Session/Load Profiles；可配置的有用事实数量；完整的操作字节与耗时统计；可选的近期上下文基准 | 独立的 profile 标识；杜绝未经验证的上下文溢出或物理删除声明 |

## 针对 `673631a` 的跟进审查

全部六项发现均已在 `tests/test_commit_673631a_regressions.py` 中建立行为回归测试覆盖：

| 发现项 | 修正方案 | 回归测试证据 |
|---|---|---|
| 交织噪声覆写了另一个受测参与者 | 从噪声断言中排除所有主参与者（primary actors） | 跨种子以及在有用事实数量为 8、14 和 64 下的可接受答案不变量；全程序请求/答案核验 |
| Bootstrap 重放丢弃了正向消融容差 | 优先使用运行工件（Run Artifact）携带的有效容差，对遗留证据回退至场景定义 | full=1, irrelevant=0.5, tolerance=0.05 的真实部分回忆运行，成功通过其 bootstrap 统计与公开报告验证 |
| 仅含有效载荷的提醒被合成虚假文本导致失败 | 在 Runner 规范化过程中保留缺失的 content | 针对缺失/规范/额外文本及文本别名的直接 Runner 与 HTTP 测试用例 |
| 非对象提醒载荷导致运行异常终止 | 在匹配前对结构化载荷进行类型检查；保留纯文本备选项 | 字符串、列表、数值、null 及无关对象在文本正确或缺失时正常评分 |
| 泄漏扫描将元数据和 JSON 键误当做事实断言 | 只检查叶子节点的值，排除合法的答案信封元数据 | 结构化、JSON 和按行键值答案；畸形元数据、解释和信源归属若泄漏禁用值仍判定失败 |
| 隐藏评测忽略了程序级阶梯覆盖配置 | 共享有效配置解析逻辑；在注册时比对并在执行前校验实例 | 跨公开/私有/校准路径匹配三/四档阶梯覆盖；拒绝不匹配配置；字符串条目保留默认值 |

这些修正均已收录在实现版本 0.10.0 与度量修订版本 0.3.0 中。程序、Profile 和报告保留其版本号；重新生成的源码锁绑定了修正后的实现。

## 验证证据

本地完整测试套件在 Python 3.12 / macOS 上报告 **299 passed, 8 skipped**，其中包括 57 个新增的跟进回归用例。在当前公开代码库上跳过了 Linux 沙箱及仅评测方可用的私有题库测试。原有用例位于 `tests/test_measurement_integrity.py`；跟进测试补充了 `tests/test_commit_673631a_regressions.py` 并强化了跨阶梯答案不变量。全部 33 个场景定义与 62 个示例场景实例均通过 schema 与语义验证。

生成的工程实验覆盖了 14 个程序在三个阶梯档位下的运行，包含 B0–B3 以及可选的有界窗口和特权参考诊断。其结果必须保持为 `same_model_engineering_stub` 且 `release_calibration_eligible: false`。它验证的是执行与报告管道，而非任务难度或基线质量。

已完成的工程运行在 42 个程序/阶梯单元上报告 `fairness_valid: true`。其配置的计划包括 558 次条件/诊断运行；没有任何一次能确立真实模型的发布就绪状态。已提交的报告与锁文件分别为 `examples/same-model/same-model-generated.stub.report.json` 和 `.stub.lock.json`。

重新生成并评分核验了八套公开 fixture 配置，覆盖 Core、M、Expanded、Session 和 Load Profiles。证据文件位于 `examples/validation/v02-review-fixture-validation.json`；重新运行 `tools/regenerate-v02-evidence.py` 可复现。在 Core 开发包上，结构化 fixture 获得 100 分，滑动窗口 fixture 获得 29.476 分，无记忆 fixture 获得 14.976 分。这些是工程 fixture，而非实证模型基线。

## 真实模型流程

1. 在 `examples/same-model/same-model-generated.external-http.json` 中配置不可变模型 ID 和无状态兼容端点。将凭证保存在指定的环境变量中。
2. 运行 `mib-same-model-calibrate <experiment> --estimate-only` 并保留实验锁文件。调用量估算是下界；观测期决策、动作延续、重试和诊断组均会消耗模型调用。
3. 运行实验并对照 `schemas/mib-same-model-report.schema.json` 验证输出。保留遥测数据、公平性检验、分程序/阶梯结果以及源码/配置锁。
4. 利用先导试验方差和预先设定的有效效应量确定独立实例数与重复次数。在声称具备跨架构通用区分度之前，测试多个固定模型并检验对程序构成的敏感性。
5. 仅在通过实证准入检验后，方可冻结评测方专属的数据包/Profile。开发策略中的阈值是暂定的；实现它们并不意味着在科学上验证了它们。

## 现存局限

会话边界由固定模型包装器强制执行，但对于任意集成的 Agent 而言仍属于声明式的实现契约。参考服务不是生产环境部署，亦非硬件证明服务。外部完整存储/写放大测量、广泛的真实领域有效性、以及从任意黑盒后端中进行物理删除，均无法从当前随附的行为测试中推定。MIB-R 保留其独立的原型结果族。
