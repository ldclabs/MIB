# MIB 的下一步：从"重放消融"到"距离上的记忆函数"

> 设计进化提案（2026-09-04），基于 `main` @ `8a41a3c`。
> **实施状态（2026-09-04，实现 0.9.0）**：第 1–3 项骨架已全部落地——`worldmodel.py`（双时态分信源世界模型、查询、支持集、泄漏证明）、`generate/`（六个 Program、干扰阶梯、反事实孪生、实例构建）、Runner 的 `swap_parameter` / 亲历任务 / `observe_only` / `maintain`、`structured` 与 `emission` 评测器、保持曲线与记忆依赖门控、`MIB-Core-0.2-Dev` Profile 与四个 fixture Agent。规范文本见 `docs/MIB-Specification.md`（v0.2）。附录 A 中可在纯代码层面落地的项目已随后实现：选择性遗忘维度（`mib.forgetting.v1`，世界模型的撤回语义）、自我规则探针、标准化负迁移对照、亲历试验的学习曲线、每个 Program 的整理窗口与 `no_maintenance` 对照、按事件/token/虚拟时间三种单位记录的距离、MIB-M Profile（0/100/1000）、BCa 区间、效率块、以及一组仅从完整条件读出的行为诊断量；仍未实现的部分列在其附录 A。
> 前提：已完成的审查修复解决的是"实现是否忠于设计"；本文讨论的是"设计本身还能走多远"。所有建议都不要求参与者改变架构，仍是黑盒可参赛。

---

## 0. 一句话结论

MIB 的论题是对的："记忆是过去参与未来计算的机制"。但现在的操作化——用重放消融测量行为差异——有一个识别性缺口：**它干预的是输入，而记忆是 Agent 的内部状态；只要过去仍在工作上下文之内，"参与"就不必经过记忆。** 在 MIB-S 尺度上，MIB 测的是阅读，不是记忆。

所以下一步进化不是再加维度、再加指标，而是把三样东西变成基准的骨架：

1. **可计算的 Oracle**：场景由一个内部的双时态、分信源的世界模型生成，答案、相关消融集、泄漏证明全部由程序推导，而不是手写。
2. **距离阶梯**：把"过去与探针之间的距离"（事件数 / token 数 / 虚拟时间 / 干扰相似度）作为主自变量，记忆能力表示为一条保持曲线，而不是一个点。距离阶梯是本基准论题的**识别条件**，不只是难度旋钮。
3. **反事实内容置换 + 亲历的过去**：因果检验从"删掉事件"升级为"改变事件内容、看答案是否跟随"；经验记忆从"读一段叙述"升级为"Agent 自己做过、失败过"。

其余都是这三样东西的推论。

## 1. 现有设计中值得质疑的四个前提

### 1.1 "移除事件后的行为差异 = 记忆的因果贡献"

`F − R` 只证明"这条信息对答案是必要的"。对任何能把整条时间线放进上下文的模型，这个差恒等于 1，而它没有动用任何记忆机制。目前 24 个公开模板每条几十个事件，全部处于这个区域。参考 fixture 100 分、无记忆 Agent 13 分，说明基准只能向下区分。

要让"参与"必须经过记忆，只有两条路：白盒操纵 Agent 状态（Memory Adapter，与黑盒承诺冲突），或者**让过去离开工作上下文**。后者就是距离阶梯。

### 1.2 "Oracle 是作者写的字符串"

手写 Oracle 带来三个结构性问题：作者错误（上一轮发现 X-001/X-002 的消融泄漏、EPI-001 无已知探针）、模板可被记忆（参数池只有 3 个值）、以及**无法扩展到 MIB-M/L**（几千个事件不可能手写）。更深的问题是：字符串 Oracle 无法表达本基准最在意的区分——"Alice 在 t 时说了什么"与"t 时什么为真"与"排除信源 X 后现在相信什么"——这些是**查询**，不是字符串。

### 1.3 "经验是被叙述的"

Experience 场景把 `tool_result` 作为**观察事件**投递给 Agent：迁移失败、诊断、恢复都是"别人告诉它发生过"。Agent 从未执行过那次失败的迁移。这测的是"叙事记忆"，不是论题里的"情境化因果轨迹"。`error_recurrence` 目前也无法诚实地测量，因为不存在"它自己犯过的错"。

### 1.4 "因果维度是一个能力维度"

Causal Memory Impact 是 (Agent, Scenario) 对的性质，不是 Agent 的能力。它存在的理由是防止"任务不需要记忆也能做对"。但这个问题应当在**校准时**由场景解决（NM 近上限的场景不进包），而不是在评分时按 Agent 加权。上一轮的门控修复止住了"不用记忆得高分"的漏洞，但根子上，这个维度应当退为诊断量。

## 2. 三个骨架性进化

### 2.1 可计算的 Oracle：场景是可执行的世界程序

**机制。** 每个场景族由一个生成器程序定义，程序内部维护一个小型世界模型：

```text
WorldModel
  claims[]      (subject, attribute, value, valid_from, valid_to)
  assertions[]  (source, claim, asserted_at, kind ∈ {state, correction, contradiction, question})
  authority     source → weight / role
  tools         state + deterministic transition
```

时间线由采样的"动作"生成：`Assert`、`Update`（世界真变）、`Correct`（认知修正，世界未变）、`Contradict`（第二信源）、`Question`（仅提问，ADV 车道）、`ToolObserve`、`Distract(confusability)`。每个动作有一组自然语言表面形式（同义改写池）。

探针不再写答案，而是写**查询**：

```text
current(alice.timezone)
as_of(alice.timezone, t=e2)
said_by(bob, meeting.start)
believed(meeting.start, exclude_source=calendar_tool)
known?(alice.allergy.shellfish)          → unknown
```

Oracle = 在世界模型上求值。由此**自动**得到：

- **相关消融集** = 使查询结果改变的最小事件集（对每个事件/事件组重新求值即可）；冗余支撑集自动识别（Transfer 文档 §3.4 手工声明的东西变成计算结果）。
- **无关集** = 移除后不改变任何探针答案的事件。
- **泄漏证明** = 答案值不能从幸存事件推导（同样的机器）。
- **反事实置换**（§2.3）= 换一个采样值重新求值。
- **难度**作为生成参数而非描述性元数据：更新次数、竞争信源数、修正链长度、干扰密度与相似度、跳数。

**与 KIP 的关系。** KIP v2 恰好定义了这个本体（命题/信念、证据/权威、有效时间/事务时间）。MIB 可以把 KIP 的本体用作**Oracle 引擎的内部表示**，而不要求参与者使用 KIP。这是两者之间最优雅的连接："KIP 是评委的世界观，不是选手的入场券"。

**收益。** 隐藏实例无上限（记忆模板失效）；Oracle 零手工错误；MIB-M/L 可生成；60 个手写模板可以退化为约 10 个生成器程序 + 少量手写的"金标准"用例。

**成本。** 世界模型 + 生成器库约 1.5–2k 行；表面形式改写池需要一次性投入（可用 LLM 生成、由结构化断言反向校验、生成后固化进实例，运行期完全确定）。

### 2.2 距离阶梯：记忆能力是一条曲线

**定义距离的三个轴：**

| 轴 | 含义 | 生成方式 |
|---|---|---|
| 时序/干扰距离 | 事件与探针之间的事件数、token 数、虚拟时间、以及中间事件的**可混淆度** | 生成器在探针前插入 `n` 个干扰事件，相似度可控 |
| 语义距离 | Transfer 文档已定义的 D0–D3 | 保留 |
| 认知距离 | 事实与探针之间经历了多少次更新 / 修正 / 矛盾信源 | 生成器控制修正链长度与信源数 |

**测量。** 同一个程序在阶梯的每一档实例化（例如干扰事件 0 / 50 / 500 / 5000），得到 `P(correct | distance)`。报告：

- **保持曲线**（Retention Curve）与曲线下面积；
- **记忆半距离**：性能相对 d=0 降到一半时的距离；
- **上下文地平线**：B1（全上下文）开始失效的距离——这是记忆系统开始互相区分的地方，也是 Track A 唯一有意义的区域。

**为什么这是识别条件而不是难度旋钮。** d=0 时任何系统都可以靠阅读；只有当过去超出地平线，正确答案才必须经过形成—保持—检索。基准的论题只有在地平线之外才被检验。现在的 MIB-S 整个位于地平线之内。

**黑盒分解形成 / 路由 / 采纳。** Transfer 层试图用白盒 Adapter 分解这三步。距离阶梯提供一个黑盒近似：

```text
d=0 就错，且 B1 也错              → 采纳/推理失败（基座模型能力）
d=0 对，随"中性"干扰衰减           → 保持/容量失败（形成或存储）
d=0 对，中性干扰不衰减、"相似"干扰衰减 → 路由/辨别失败（检索）
```

用**干扰的类型**而不是内部钩子来分解，架构中立且对所有参赛者可用。

**分数语义。** 维度分 = 曲线在 Profile 指定的**规范档位**上的值（例如 MIB-M 取 d=500），曲线整体作为 Memory Profile 报告。这样 MIB Score 仍是一个数，但它的含义从"读得对不对"变成"在这个距离上还记不记得"。

### 2.3 反事实内容置换与亲历的过去

**内容置换（do-calculus on content）。** 不删除相关事件，而是把它的值换成另一个采样值（UTC+1 → UTC+2），正确答案随之改变。指标：

```text
Content Tracking Rate = P(答案跟随反事实值)
```

它比移除更强：移除可被先验或猜测饱和（这正是 HMB 饱和的原因），跟随则要求事件内容到答案之间存在真实的因果通路。它天然处理冗余记忆（只换其中一个冗余事件，答案不应只跟随一个），也让 ADV 车道更锋利（换掉提问中预设的值，任何跟随都是"提问被沉淀为事实"的直接证据）。在可计算 Oracle 下，置换消融是免费的。

**亲历的过去。** 允许 `past` 阶段包含 `act` 任务：Agent 自己执行、自己失败、自己恢复，其工具轨迹成为它的经验；未来探针检验它是否避开**自己**的已知失败。这才是论题中的"情境化因果轨迹"，`error_recurrence` 也第一次可以诚实测量。实现要点：世界模拟器按阶段做检查点/恢复，使未来任务的初始世界状态在各条件下一致；"移除经验"= 重放时跳过过去任务并恢复检查点。

## 3. 由骨架推出的其余进化

### 3.1 结构化答案、"评委只做解析器"、认知校准

探针声明 `answer_schema`：`{value, status, as_of?, according_to?, confidence?}`，逐字段确定性评分。这直接解决"UTC+1（之前是 UTC+8）"被判陈旧采纳的困境：`{current: UTC+1, previous: UTC+8}` 完全正确。弃权成为一等公民（`status: unknown`）。

自由文本 Agent 通过一个抽取步骤映射到 schema；若需要 LLM，它只做"文本 → 结构"的解析，**从不打分**，解析结果落盘可审计，确定性规则优先、LLM 解析器兜底。

`confidence` 字段启用 Brier 类评分——**认知校准**：修正链之后说"我不确定"应当好于自信地给出陈旧值。这是论题里"保留不确定性"第一次被计分。

### 3.2 巩固窗口与前瞻记忆

- `maintenance_window` 触发 Adapter 的 `maintain(run_id, budget)`；所有系统获得相同窗口；诊断量"巩固收益"= 有窗口 vs 无窗口的差。离线巩固是记忆研究的主线之一，目前没有任何基准测它。
- `observe_only` 探针 + 对 `emissions` 计分：触发检测、及时性（以事件数计）、无过早触发。前瞻记忆是最"智能体"的记忆能力，协议里的 `emissions` 通道已经存在，只差评测器。

### 3.3 预算下的记忆：选择性才是智能

现有探针只奖励"记住"，从不约束代价；一个存下一切、召回一切的系统在 MIB-S 上通吃。让 `usage`（每次探针注入的召回 token、存储规模）在 Track A 成为必报项（同模型 harness 本就控制提示，token 可精确计量），报告**每召回 token 的正确率**与"能力—召回预算"前沿。这把 KIP 里的显著性/记忆强度思想变成可测量的东西："记忆智能 = 在预算下选对该记的。"

### 3.4 因果维度退为诊断，"记忆依赖"变成资格

MIB Score = 规范档位上的能力分。因果量（MB、HMB、IMS、HRS、Content Tracking）全部作为 Memory Dependence Profile 并列报告；资格门槛：场景在校准时 MDI 高于阈值（任务确需记忆），Agent 的 Content Tracking 高于地板（分数确经记忆取得，而非先验）。这比按权重混入更清楚，也消除了"分数中有多少来自记忆"的模糊。

### 3.5 统计设计

生成器让实例便宜，设计单元从"模板"变为"程序"；bootstrap 同时在程序层与实例层重采样，每维度最少模板数的门槛改为最少程序数。阶梯上可做序贯检验（某档的置信区间一旦离开阈值即停止）。榜单成熟后可引入 IRT 式难度校准：实例难度由多系统估计，单系统只需少量实例即可得到带不确定性的能力估计。

### 3.6 抗污染

生成实例 + 改写池 + **晚采样探针类型**（哪一类查询触发在触发时才决定，而不只是措辞变体）使按措辞模式匹配失效；每个隐藏实例携带唯一表面值，泄漏可溯源。

## 4. 应该停止或缩小的事

- **停止再手写模板**。现有 24 + 36 个手写模板保留为生成器的验收金标准；新内容一律来自生成器。
- **参考 fixture Agent 不再投入**。它按措辞分支，只能证明管道通。生成器验收改用"程序化 Oracle 自检"（同一世界模型上的另一个求值器）。
- **Memory Adapter 与 2×2 矩阵保持 experimental**。§2.2 的黑盒分解覆盖了它的主要用途；白盒路径只对愿意暴露内部的系统作为附加诊断。
- **MIB-R 先定义接口，再接真实环境**。LedgerCodes 是占位符；有价值的现实环境是"跨会话重复出现的真实任务集"（例如同一代码库上的连续维护任务），记忆在会话之间才有意义。
- **六个维度的权重是政策而非发现**。拿到真实模型数据后做一次因子分析；时序与认知记忆很可能高度相关，维度可能合并或重划。

## 5. v0.2 的最小落地集

按依赖顺序，每项都是可独立交付的增量，且在生效前不改变 v0.1 分数语义（新量先以报告扩展块并列输出）。

| # | 交付物 | 主要改动 | 规模 |
|---|---|---|---|
| 1 | 世界模型 + 3 个生成器（Time / Epistemic / Recall），可计算 Oracle、自动消融集与泄漏证明 | 新包 `mib_runner/generate/`；schema 加 `template.program`、probe `query`；`ablation.method: swap_parameter` | ~2k 行 |
| 2 | 干扰阶梯与保持曲线 | 生成器 `interference_ladder`；报告扩展 `mib.retention.v1`（曲线、半距离、地平线）；Profile 加 `canonical_rung` | ~600 行 |
| 3 | 结构化答案与解析器 | probe `answer_schema`；`structured` 评测器；`confidence` 的 Brier 评分 | ~400 行 |
| 4 | 亲历的过去 | `past` 阶段允许 `type: task`；世界模拟器阶段检查点；`error_recurrence` 计量 | ~500 行 |
| 5 | 巩固窗口与前瞻发射 | Adapter `maintain`；`observe_only` 探针与 emission 评测器 | ~400 行 |
| 6 | 同模型 harness × 阶梯 | B0–B3 在各档位运行；发布"固定模型下各记忆系统的保持曲线"——这是 MIB 的头版图 | 复用 |
| 7 | 用真实模型校准，冻结 v0.2 语义：规范档位能力分 + Memory Profile + 记忆依赖资格 | Profile 与文档 | — |

第 1–3 项完成后，就可以用一个生成器产出第一个 MIB-M 包，并回答那个至今无法回答的问题：**在全上下文失效之后，哪种记忆系统还记得。**

## 6. 不变的东西

以下设计已被证明是对的，进化应保留它们：黑盒 Adapter 与四个操作；Runner 拥有世界与时钟、Agent 不能直接改世界；未来探针不泄漏；每个条件新建 Agent 且配对；Template（程序）优先聚合；隐藏实例化与别名化；能力分与因果量分开报告；评测优先确定性与世界状态；可从报告复算分数。

---

## 7. 一段话给读者

如果 v0.1 的问题是"它记得吗"，v0.2 的问题应当是：**"离开了上下文之后，它在多远处还记得，记得的是不是它自己经历的，改变的是不是它记住的那件事，以及它为此花了多少。"** 这四个问题分别对应距离阶梯、亲历的过去、内容置换与预算下的记忆。回答它们不需要参与者改变任何架构，只需要基准把 Oracle 从作者的手里交给一个能被证明正确的程序。
